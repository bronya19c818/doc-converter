## 应修复项是覆盖率分母，映射动作不等于正确修复

旧 `auto_coverage=action:mapped/非preserved` 只说明发生过映射，不能衡量正确修复。v2 使用独立标签的 `needs_repair`：标题标记层级错误、元数据待抽取、题注/参考文献待套用专用样式。必须角色符合标注，实际完成标记/元数据调整，或输出专用样式正确，才计入正确自动修复。仅修改为错误层级不计通过；错误自动更改另计误修，未正确完成的应修项计漏修。无应修项时覆盖率返回 null。

Precision/Recall 只衡量“是否标题”；层级正确率以全部真实标题为分母，漏识别及错误级别都会扣分。最终 DOCX 样式核验读取人工标签应有的样式和大纲，不以系统选出的角色作为 ground truth。转换运行时还额外检查请求样式包与实际有效段落格式及字体。

## 样本是开发评估集，不代表真实业务总体正确率

标签在分类执行前按业务层级、源语法和修复任务定义，未使用分类器输出生成。独立样本保留了长标题、稀疏家族、编号变化、无子正文序列、正文操作句、虚拟父节点、真实未编号父标题、复杂语法、元数据和附录。长报告的重复正文只标注首段，其余仅增加性能负载，不扩大正确率分母。

这组样本用于开发诊断及回归，经过失败案例修复后达到当前结果，属于受控开发评估，不是未见材料盲测或随机真实客户样本。缺失上下文的短行、超过六级的层级、无附件图片以及实际文档复杂排版仍需业务复核；产品不要求所有输入 100% 准确，也不以降低处理比例作为目标。

基线固定加载上述提交的 `normalizer.py`、`markdown_preprocess.py`、`markdown_scoring.py`。两版使用相同进口适配器、Pandoc、输出核验器和样式包，以隔离评分与结构差异；DOC 导入异常修复另列架构变更，不包装成评分提升。全部报告和实际输出由 CI artifacts 提供。

复现：

```bash
uv run python scripts/verify_markdown_scoring.py --output artifacts/markdown-baseline --render
uv run python scripts/verify_markdown_scoring.py --fixtures tests/fixtures/markdown_complex --render --baseline-ref c63f1bd75c14ac8cca99a017540ef7c3fb8dbd92 --output artifacts/markdown-complex
```

代码审查发现的冲突决策、幂等及有效字体核验问题均建立 RED→GREEN 用例；真实 DOC 评估进一步修复原生 Title 丢失、逻辑对齐值和转义编号片段拼接问题。最终验证状态及 CI 链接记录于 PR #2。
